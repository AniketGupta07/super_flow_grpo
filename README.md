# VPS: Video Preference Score with Flow-GRPO

This repository implements **Video Preference Score (VPS)** training using the Flow-GRPO algorithm on Wan2.1 video generation models. VPS enables fine-tuning video generation models using human preference data through online reinforcement learning.

## Overview

VPS uses a learned preference reward model to guide the training of video generation models. The reward model predicts which of two videos better matches human preferences, and this signal is used to optimize the video generator via the Flow-GRPO algorithm.

**Key Components:**
- **Flow-GRPO**: Online RL algorithm for flow matching models ([Liu et al., 2025](https://arxiv.org/abs/2505.05470))
- **Wan2.1**: Text-to-video generation model as the base generator
- **Preference Reward Model**: MLP-based model trained on human preference data

## Quick Start

### 1. Environment Setup

```bash
git clone <repository-url>
cd flow_grpo
conda create -n vps python=3.10.16
conda activate vps
pip install -e .
```

Additional dependencies for the reward model:
```bash
pip install sentence-transformers qwen-vl-utils
```

### 2. Download Models and Data

**Base Video Model:**

Download Wan2.1-T2V from HuggingFace and place in `hf_cache/`:
```bash
# Wan2.1-T2V-1.3B (recommended for single-GPU training)
huggingface-cli download Wan-AI/Wan2.1-T2V-1.3B-Diffusers --local-dir hf_cache/Wan2.1-T2V-1.3B-Diffusers

# Wan2.1-T2V-14B (for multi-GPU training)
huggingface-cli download Wan-AI/Wan2.1-T2V-14B-Diffusers --local-dir hf_cache/Wan2.1-T2V-14B-Diffusers
```

**VPS Preference Data:**

Download the VPS dataset from HuggingFace:
```bash
huggingface-cli download supervideoVPS/super_video --repo-type dataset --local-dir data/super_video
```

This dataset contains:
- `dataset.json` - Video metadata with prompts and indices
- `videos/` - Video files for preference training
- Pre-trained PairMLP reward model weights (`best.pth`, `config.json`)

### 3. Generate Embeddings

Before training, generate the required embeddings from the downloaded data:

**Prompt Embeddings (SBERT):**
```bash
cd VPS_reward
python prompt_encoder.py \
  --input ../data/super_video/dataset.json \
  --output ../data/super_video/SBERT_PROMPT_EMBEDDINGS.json
```

**Vision Embeddings (Qwen2.5-VL):**
```bash
python vision_only_encoder.py \
  --input ../data/super_video/dataset.json \
  --video-dir ../data/super_video/videos \
  --output ../data/super_video/VIDEO_ONLY_EMBEDDINGS.json
```

### 4. Set Up Environment Variables

The reward functions require environment variables to locate data and models:

```bash
# Directory containing embeddings and prompts
export VPS_DATA_ROOT=/path/to/your/data
# Should contain:
#   - extended_prompts.txt (or copy from data/extended_prompts.txt)
#   - SBERT_PROMPT_EMBEDDINGS.json (generated by prompt_encoder.py)
#   - video_encodings/wan_ref_vision_embeddings*.json (generated by embed_wan_ref_grpo_videos.py)

# Directory containing PairMLP reward model
export VPS_MODEL_DIR=/path/to/data/super_video/VPS_models/both
# Should contain: best.pth, config.json (from HuggingFace dataset)
```

### 5. Start Training

**Single-node training with 4 GPUs:**
```bash
accelerate launch \
  --config_file scripts/accelerate_configs/multi_gpu.yaml \
  --num_processes=4 \
  --main_process_port 29501 \
  scripts/train_wan2_1.py \
  --config config/grpo.py:preference_wan2_1
```

**For testing/debugging (fewer batches):**
```bash
accelerate launch \
  --config_file scripts/accelerate_configs/multi_gpu.yaml \
  --num_processes=1 \
  --main_process_port 29501 \
  scripts/train_wan2_1.py \
  --config config/grpo.py:preference_wan2_1_test
```

## Configuration

The main configuration is in `config/grpo.py`. Key settings for VPS:

```python
def preference_wan2_1():
    config.pretrained.model = "hf_cache/Wan2.1-T2V-1.3B-Diffusers"
    config.height = 240
    config.width = 416
    config.frames = 33
    
    # Sampling settings
    config.sample.num_steps = 20
    config.sample.guidance_scale = 4.5
    config.sample.train_batch_size = 8
    config.sample.num_image_per_prompt = 8
    
    # Training settings
    config.train.learning_rate = 1e-4
    config.train.beta = 0.004  # KL loss weight
    config.train.clip_range = 1e-3
    
    # Reward function
    config.reward_fn = {"preference_cached_refs": 1.0}
```

### Important Hyperparameters

| Parameter | Description | Recommended |
|-----------|-------------|-------------|
| `train_batch_size` | Videos per GPU per batch | 8 |
| `num_image_per_prompt` | Group size for GRPO | 8 |
| `num_batches_per_epoch` | Batches before update | 2 |
| `beta` | KL divergence penalty | 0.004 |
| `clip_range` | PPO clip range | 1e-3 |
| `learning_rate` | Adam learning rate | 1e-4 |

## VPS Reward Directory

The `VPS_reward/` directory contains scripts for training and evaluating the preference reward model:

### Embedding Generation
- `prompt_encoder.py` - Generate SBERT prompt embeddings
  ```bash
  python prompt_encoder.py --input <dataset.json> --output <embeddings.json>
  ```
- `vision_only_encoder.py` - Generate Qwen2.5-VL video embeddings
  ```bash
  python vision_only_encoder.py --input <dataset.json> --video-dir <videos/> --output <embeddings.json>
  ```

### Data Preparation
- `data/` - Prompt files and reference ELO scores
  - `prompts.txt`, `extended_prompts.txt` - Text prompts for video generation
  - `i2v_final.csv`, `t2v_final.csv` - Reference ELO leaderboards

### Reward Model Training
- `create_prompt_splits.py` - Create train/val/test splits ensuring prompt disjointness
- `train_prompt_pair_mlp.py` - Train the PairMLP preference predictor

### ELO Reconstruction
- `reconstruct_elo_from_probs.py` - Reconstruct model ELO scores from predicted probabilities
- `reconstruct_elo_prompt_models.py` - ELO reconstruction with prompt-specific models

### Streaming Models
- `streaming_models/` - Scripts for training models that handle streaming data
  - `create_prob_splits.py` - Create probability-based splits
  - `train_pair_mlp.py` - Train streaming-compatible MLP
  - `reconstruct_elo_streaming_models.py` - ELO from streaming predictions

### Visualization
- `neurips_plots/` - Scripts for generating publication figures
  - `make_leaderboard_plots.py` - Model leaderboard visualizations
  - `make_arena_plot.py` - Arena-style comparison plots

## Reward Model Architecture

The VPS reward model uses a PairMLP architecture:

**Input Features (7552 dimensions):**
- Video 1 vision embedding: 3584 dim (Qwen2.5-VL)
- Video 2 vision embedding: 3584 dim (Qwen2.5-VL)  
- Prompt embedding: 384 dim (SBERT)

**Network:**
```
Linear(7552 → 8192) → LayerNorm → GELU → Dropout(0.35)
Linear(8192 → 4096) → LayerNorm → GELU → Dropout(0.35)
...
Linear(64 → 4) → LayerNorm → GELU → Dropout(0.35)
Linear(4 → 1) → Sigmoid
```

**Output:** Probability that video 1 is preferred over video 2.

### Training a New Reward Model

If you want to train your own reward model instead of using the pre-trained one:

```bash
cd VPS_reward

# Create train/val/test splits based on prompts
python create_prompt_splits.py --dataset both

# Train the preference prediction MLP
python train_prompt_pair_mlp.py --dataset both
```

## Checkpoints

Training checkpoints are saved to `logs/video_preference/<run_name>/` including:
- LoRA adapter weights
- Optimizer state
- Training metrics

To resume training:
```python
config.resume_from = "logs/video_preference/wan_flow_grpo_preference/checkpoint-XXX"
```

## Monitoring

Training progress is logged to Weights & Biases. Key metrics to monitor:
- `reward/mean` - Average preference score
- `reward/std` - Reward standard deviation
- `train/loss` - Policy loss
- `train/kl` - KL divergence from reference model

## Tips

1. **Precision**: Use `bf16` for Wan2.1 (fp16 produces invalid videos)
2. **Batch size**: Adjust `train_batch_size` based on GPU memory
3. **Clip range**: Use small values (1e-3) for Flow-GRPO-Fast stability
4. **KL penalty**: Start with `beta=0.004`, increase if outputs degrade
